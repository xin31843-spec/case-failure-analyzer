# Machine Learning Interatomic Potentials Knowledge Base (`mlip`: MACE, NequIP, Allegro, DeePMD-kit, CHGNet, SevenNet, M3GNet, MatterSim, Orb)

This reference defines the diagnostic error families, candidate causes, and required discriminating evidence for Machine Learning Interatomic Potentials (`MACE`, `NequIP`, `Allegro`, `DeePMD-kit`, `CHGNet`, `SevenNet`, `M3GNet`, `MatterSim`, `Orb`, `SchNetPack`, `TorchMD-Net`).
Remember: **Matching an error family does NOT automatically blame the agent.**

## Error Families

| Error Family | Signature Patterns | Candidate Causes | Required Discriminating Evidence |
|---|---|---|---|
| `checkpoint_architecture_incompatibility` | `Error(s) in loading state_dict`, `WeightsOnlyLoadWarning.*UnpicklingError`, `Weights only load failed`, `cuequivariance.*not available`, `No such file or directory:.*\.(model\|pt\|pth\|ckpt\|pb)` | `pytorch_weights_only_true_blocking_mace_nequip_checkpoint`, `missing_local_foundation_model_checkpoint_path`, `mismatch_between_mace_nequip_deepmd_version_and_checkpoint_hyperparameters` | Check checkpoint file existence, `torch.load(..., weights_only=False)` compatibility, and installed MLIP package version |
| `mlip_rollout_ood_instability` | `RuntimeError:.*neighbor.*cutoff`, `NaN detected in predicted forces`, `MLIP forces exceeded .* eV/A`, `zero neighbors found for atom` | `out_of_distribution_atomic_overlap_triggering_repulsive_hole`, `missing_zbl_pair_repulsion_prior_at_high_temperature`, `non_periodic_cell_without_pbc_true_during_bulk_rollout` | Inspect minimum interatomic distance ($r_{ij}$) and max atomic force ($\max \|F_i\|$) prior to rollout divergence |
| `element_embedding_z_unsupported` | `Atomic number .* not in model`, `type_map.*does not contain`, `Unsupported element .* for potential`, `KeyError:.*atomic_numbers` | `trained_mlip_potential_missing_species_in_z_table_or_type_map`, `wrong_chemical_symbol_mapping_in_deepmd_type_raw` | Compare `atoms.get_chemical_symbols()` against the MLIP checkpoint's `atomic_numbers` / `type_map` list |
| `device_dtype_oom_error` | `CUDA out of memory`, `Expected all tensors to be on the same device`, `Input type (torch.*DoubleTensor) and weight type (torch.*FloatTensor)`, `mat1 and mat2 must have the same dtype` | `float64_ase_positions_passed_to_float32_mlip_model_or_vice_versa`, `supercell_graph_edges_exceeding_gpu_vram_without_batching_or_cpu_fallback`, `mixed_cpu_cuda_device_placement` | Inspect `default_dtype` (`float32` vs `float64`), `device` argument (`cpu` vs `cuda`), and supercell atom/edge count |
| `energy_reference_unit_offset` | `formation_energy.*mismatch.*isolated atom`, `reference_energy.*offset`, `E0s.*not subtracted` | `comparing_mlip_cohesive_energy_directly_against_dft_total_energy_without_e0_shift`, `mixing_ev_per_atom_with_total_supercell_energy_or_kcal_mol` | Check whether per-element isolated atom reference energies (`E0s`) or per-atom normalization (`/ len(atoms)`) were applied |
